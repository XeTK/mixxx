# 09 — Bug batch 2026-07-20: what landed, what's waiting on Tom

## Landed this batch (see git log around 2026-07-20)

- **Master/headphone volume readout**: now plain knob travel
  ("Headphone volume a quarter"), was center-split ("minus a half")
  which read as negative volume. Half of travel = unity.
- **Name-on-touch + name-once + jitter suppression for knob/fader
  readouts**: keyed `announceControlDebounced(key, name, value)`
  overload in `AnnouncementManager`. The first movement of a control
  speaks its NAME immediately ("Deck 1 volume"); the VALUE is
  debounced until it stops ("three quarters"). Same control moving
  again within 8 s (`kControlContextMs`, refreshed while it moves)
  speaks values only. `m_lastValueByKey` (session-lifetime hash) is
  the jitter/no-change guard: a readout equal to the last one spoken
  for that key produces nothing at all — gate applies to the touch
  name too, or the worn "Alpha" mid-EQ pot would chant its NAME
  instead of its value. Any other announcement resets the context
  (cleared in `speak()`, restored around the control speaks). The
  repeat key re-speaks the full wording. Pitch fader was split so the
  touch name is "Deck 1 pitch" and the value "up 2 percent. 174 BPM"
  (`pitchDeviationText`). "Announce while moving" bypasses
  name-on-touch (it already speaks immediately).
- **Cue preview earcon**: `EngineEarcon::Id::CuePreview` (988 Hz, 40 ms
  single tick) replaces the unconditional "Cue" speech; gated by
  `FeedbackModeCue` like headphone cue. "Cue cue cue" fixed by setting
  that combo to Sounds.
- **Load blocked reason**: `WTrackTableView::loadSelectedTrackToGroup`
  speaks "Deck N is playing, load blocked. Stop the deck first." when
  `LoadWhenDeckPlaying` = Reject (the silent-return branch).
- **Search result count**: `WTrackTableView::onSearch` reports
  `model()->rowCount()` through `Library::announceSearchResultCount` →
  "Searching: techno. 42 tracks". Signal-order note: the manager
  connects to `Library::search` before the skin connects
  `Library::search → WLibrary::search`, so the count-reset always runs
  before the count arrives.
- **Deck quick-add**: `[ChannelN],quick_add_to_playlist` /
  `quick_add_to_crate` COs (LibraryControl, decks 1-4) open the
  existing spoken pickers for the deck's loaded track
  (`PlayerInfo::getTrackInfo`). Keys: Ctrl+Alt+P / Ctrl+Alt+C, +Shift
  for deck 2, all 12 layouts.
- **BPM halve/double**: Ctrl+Alt+H / Ctrl+Alt+D (+Shift deck 2) bound
  to the existing `beats_set_halve/double` COs; announced ("B P M
  halved") without the number (reading bpm back immediately races the
  engine — tts_bpm has the number).
- **Quantize keys**: Ctrl+Alt+Q (+Shift deck 2) — there was no
  keyboard binding at all for quantize.
- **Controller shift/pad-mode feedback**: new manager-owned COs
  `[Tts],shift` (speaks "Shift" on press only) and `[Tts],pad_mode`
  (fixed vocabulary 1-9, same-value writes silent — this absorbs the
  Numark mode button firing for both decks). Wired: Numark Scratch
  (shift + mode selector announces Hotcue/Loop roll/Sampler), DDJ-400
  (shift; all 8 pad-mode buttons via 16 new XML bindings).
  **CAUTION**: the DDJ-400 mode-button MIDI numbers (0x90/0x91 notes
  0x1B/0x6D/0x20/0x22/0x69/0x1E/0x6B/0x6F) were taken from the
  DDJ-FLX4 mapping in this repo (same Pioneer pad protocol) because
  Pioneer's DDJ-400 MIDI PDF is offline — worst case wrong numbers =
  silent no-op, but **needs a hardware test**.

Tests: 210 a11y tests green (was 199); suite additions in
`announcementmanager_test.cpp` and `engineearcon_test.cpp`.

## Gotchas rediscovered this session

- Fresh worktree configure MUST pass the vcpkg toolchain file
  (`-DCMAKE_TOOLCHAIN_FILE=...buildenv...\scripts\buildsystems\vcpkg.cmake`)
  **on the very first configure**. A failed first configure (missing
  Qt6) leaves `build/CMakeFiles/<ver>/` compiler-detection cache that
  makes a later toolchain configure map protobuf/qtkeychain imports to
  DEBUG (`libprotobuf-lited.dll` in build.ninja). Fix: `rm -rf build`
  and reconfigure. Verify with
  `grep -c libprotobuf-lited build/build.ninja` → must be 0.
- Git-bash mangles `cmd /c` (`/c` → `C:\`); use `cmd //c` and
  absolute paths in helper `.cmd` scripts.
