Branch 1 — feat/accessibility-spoken-track-info

What is done

  • Windows SAPI TTS engine via ISpVoice COM interface
  • TtsEngine abstract interface for future platform swap-in
  • AnnouncementManager wired into CoreServices
  • Track selection announcement (400 ms debounce) — artist and title
  • Track load announcement — artist, title, BPM, key
  • AccessibilitySettings with AnnounceTrackSelection and AnnounceTrackLoad toggles
  • Preferences page DlgPrefAccessibility with two checkboxes, registered in DlgPreferences
  • Unit tests: format helpers, selection/load gating (13 tests)

Outstanding — must fix before PR

  • Windows only. SapiTtsEngine uses ISpVoice COM — no macOS or Linux implementation exists. Options:
    • Add Qt6TextToSpeech to vcpkg.json and replace the SAPI backend — cleanest cross-platform path but requires dependency work.
    • Add platform-specific backends: macOS NSSpeechSynthesizer, Linux espeak-ng.
  • Audio routing. TTS plays through the OS default audio output and will bleed into the master mix on a single-output setup. Needs routing to the cue/headphone output. Long-term fix requires QAudioSink or Qt6TextToSpeech with a custom audio device selector.

Outstanding — nice to have

  • Preferences page uses a placeholder icon (ic_preferences_interface.svg). A proper accessibility icon would be better.
  • No announcement when a track is ejected/unloaded — could say "Deck cleared".

Branch 2 — worktree-feat-accessibility-playstate-announcements

This branch stacks on top of Branch 1. All Branch 1 issues apply here too.

What is done

  • Play announcement — "Playing" when a deck starts (gated by track-loaded state)
  • Stop announcement — "Stopped" when a deck is paused by the user
  • End-of-track announcement — "End of track" when the CO fires
  • Stop suppression — "Stopped" is silenced when end-of-track caused the stop
  • "Mixxx ready" on MixxxMainWindow::skinLoaded
  • Library pane focus announcement — "Search bar", "Sidebar", "Track list" via [Library] focused_widget CO
  • All-deck fix — getDeckBase is 0-indexed; was accidentally skipping Deck A
  • Session restore fix — getLoadedTrack() pre-populates m_deckHasTrack at startup
  • AnnouncePlay, AnnounceStop, AnnounceEndOfTrack, AnnounceLibraryFocus settings added to AccessibilitySettings
  • Checkboxes for Play / Stop / End-of-track in dlgprefaccessibilitydlg.ui
  • CoreServices::getAnnouncementManager() getter for MixxxMainWindow hookup
  • 8 new unit tests for playstate announcements

Outstanding — must fix before PR

  • Missing UI for Library Focus toggle. AnnounceLibraryFocus exists in AccessibilitySettings but has no checkbox in the prefs UI. Need to:
    • Add checkBoxAnnounceLibraryFocus to dlgprefaccessibilitydlg.ui
    • Add bool m_bAnnounceLibraryFocus to DlgPrefAccessibility
    • Wire it up in slotUpdate, slotApply, slotResetToDefaults
  • Inherits all Branch 1 blockers (Windows-only TTS, audio routing).

Outstanding — nice to have

  • CDJ CUE hold debounce. In CDJ mode, holding CUE fires play then stop in quick succession, producing "Playing" immediately followed by "Stopped". A short debounce (e.g. 300 ms) on the stop announcement would prevent this false positive.
  • Deck identity in announcements. With two decks active, "Playing" is ambiguous. Consider "Deck A playing" / "Deck B stopped" or speaking the track name on play.
  • No test coverage yet for the library focus slot (slotLibraryFocusChanged) or the skin-loaded slot (slotSkinLoaded).
  • 4-deck support not verified — only 2-deck setups have been tested.

Suggested merge order

  1. Resolve the audio routing / cross-platform TTS blocker (or scope the PR explicitly to Windows with a tracking issue for other platforms).
  2. Land feat/accessibility-spoken-track-info first — it is the foundation.
  3. Add the missing checkBoxAnnounceLibraryFocus UI to Branch 2.
  4. Address CDJ CUE debounce if testing reveals it is noisy in practice.
  5. Land worktree-feat-accessibility-playstate-announcements on top.
